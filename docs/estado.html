02 Lo que es solo diseño

Las cinco rutas de suscripción. Ninguna cobra y ningún botón hace nada. El estado se lee de ?estado= en la URL porque no hay tabla de suscripciones.

Lo que sí está resuelto y es permanente:

  • Las cifras viven en lib/plan/datos.ts, no dentro de los textos. Cambias el precio en un sitio y se actualiza en las dos pantallas y los dos idiomas.
  • El día del aviso se calcula (7 − 2 = 5), no está escrito.
  • La aritmética de fechas usa setDate, no sumar milisegundos. Con el cambio de hora eso se va un día.
  • Las tipografías que faltaban (Bricolage Grotesque e Instrument Sans) ya cargan. Sin ellas todo caía en Segoe UI y se veía más grande de lo diseñado.
El día 7 sigue sin decidirse. Qué pasa con alguien que entró durante la prueba cuando llega el cobro. Ahora se esquiva borrando las cuentas de prueba, pero no desaparece: es la decisión de producto más grande de todo el bloque.

04 Lo último que se hizo

Lote 1: que la app pueda salir de tu ordenador. Es lo único que hace falta para poder desplegar. Sin eso no hay formulario de 4Geeks que rellenar.

FicheroPara qué
requirements.txtLas 13 librerías con tus versiones probadas, no las más nuevas
.python-version3.14, la misma que usas tú
.env.examplePlantilla con el aviso del +psycopg2
app/security.pySECRET_KEY falta al arrancar, no en el primer login
app/database.pypool_pre_ping para que Neon no dé errores al despertar
web/app/login/page.tsxLa URL del backend por variable de entorno
web/app/dashboard/page.tsxLo mismo
El hallazgo del driver. SQLAlchemy 2.1 busca psycopg3 cuando la URL no dice nada, no lo encuentra y la app no arranca. Pasaba solo con la URL de Neon, que viene sin driver: en local funciona porque tu .env lo lleva escrito. Se resuelve con +psycopg2 en la URL, no bajando de versión. Así local y producción usan lo mismo.
Y una trampa del entorno. PowerShell borra la variable cuando la pones vacía, en vez de dejarla vacía. Una prueba manual dijo que el SECRET_KEY funcionaba cuando no. La prueba de verdad es por subprocess, que es como están hechos los tests.

05 Cómo levantarlo

# Docker Desktop tiene que estar abierto. Sin él, se cae el backend.

cd C:\trademind\web        npm run dev          # la web, en :3000

cd C:\trademind
.\venv\Scripts\python.exe -m pytest            # 300 tests de backend
cd web; npm test                                # 167 tests de frontend
cd web; npx tsc --noEmit                        # los tipos
cd web; npm run build                           # que compile de verdad

Como el backend es Python y la web Next.js, hay dos carpetas con su propio package.json. Regla fácil: si el comando lleva npm, estás en web. Si lleva pytest, alembic o docker, estás en la raíz.
